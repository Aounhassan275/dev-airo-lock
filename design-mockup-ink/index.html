Airo Access Lock & Control

The same screens, with the accent in ink rather than violet. What is selected, current, running or part-done is marked by weight and contrast instead of by hue — which is how the Shopify admin and the apps that sit well inside it behave.

It is one ramp apart from design-mockup-black/: ten lines in :root, and nothing else in either folder differs. Content types keep their own colours in both, because those are the app’s and they carry meaning rather than brand.

The design language

Three pieces, shared by every screen from assets/app.css rather than copied between them.

--accent Weight, not hue One ramp drives every tint on every screen: ticks, meters, section numbers, the selected row. Here it is ink, so emphasis comes from contrast — and the violet version of this folder is one ramp away.
.stage A dark mount for the shopper's view A white popup on a white card has no edge and reads as empty space. On black it reads as a screen.
.opt The whole row is the target Pickable rows that take the accent border and a tick when chosen, instead of bare radio buttons with a label beside them.

What the restyle changed

The plan banner stopped shouting.

It was a three-stop violet gradient with decorative circles and a coloured glow. It is now a flat black panel with a hairline border, so it reads as a system message about the merchant's account rather than as an advertisement inside their own admin.

Colour now means something.

The app’s violet is the accent again, but it only marks what you can act on and where you are: primary buttons, the current step, the chosen card. Blue stays for links, green for confirmations and feature ticks. Everything that was violet purely for emphasis is black or grey.

Icons are monochrome.

Twenty-six colour emoji — shields, bolts, rockets, padlocks — became stroked SVGs that inherit the text colour. An orange lightning bolt beside a black heading undoes a neutral palette faster than anything else on a page.

Things worth knowing when reading these

The lock builder is not a wizard.

The file is called LockCreationFlow.jsx and there is a StepIndicator component in the folder, but the screen that ships is a single page with a 1fr / 340px grid. The step indicator is unused by it.

Two design languages sit side by side.

Polaris supplies the page frame, cards and table; the violet banner, stat cards and plan cards are hand-written inline styles. They do not share tokens, so the greys come from two different palettes — Polaris #616161 next to Tailwind #9ca3af.

Lock conditions are one flat group.

The builder renders groups[0] only, with an AND/OR operator and a row per condition. There is no second group in the UI even though the data model allows one.

Popup wording lives in a modal.

It is reached from a button inside the Widgets card in the right-hand column, rather than having a card of its own.

Static HTML, CSS and a little JavaScript. No framework and no build step — open any file directly in a browser. Counts, names and dates are invented; every label, heading, badge and colour is taken from the source.
